**Finding**

1. **P2 — An older health response can still overwrite a newer running build within the same source.** `web/app.js:1171`, publication at `web/app.js:1182`; overlap enters through `web/app.js:2537` and `web/app.js:2503`.

   Exact reproduction: with the game link selected and watching, start a watcher health read whose response body says `runningBuild: 0`, and hold that body. Click Update while the watcher is still reading. Let `/refresh` return 429 with `retryAfter: 1`; its subsequent health read returns `runningBuild: 3682` and the same save stamp. The page correctly publishes 3682. Release the older watcher's body before the retry finishes, then let the retry return 409/saving. No source change occurs throughout.

   Expected: the older response cannot replace metadata already published by a newer health read. The report/footer should retain game 3682. Actual: publication callbacks are `[3682, null]`; `reportContext().runningBuild()` becomes null and remains null after Update completes. An older positive response similarly replaces 3682 with that obsolete number. This can erase the running version in a report and repaint the footer/build warning from stale data until another health response corrects it.

   Both generation and URL comparisons pass because these requests belong to the same source. `update()` does not wait for `watchChecking`, so this is a reachable watcher/Update overlap, not just two arbitrary direct calls to `readHealth()`. Track publication ordering within a source (or otherwise serialize/suppress obsolete health publication), and add this overlap to the regression tests. The existing new tests cover source transitions but not response ordering within one source.

   Evidence: `extended-health-probe.cjs/.log` reproduces older zero, omitted, and positive running builds through the production watcher and Update functions. `browser-order-probe.cjs/.log` independently confirms the zero case in Edge with production `app.js`, real `Response`/`ReadableStream` bodies, and the actual one-second retry: `{before:3682, after:null, afterUpdate:null, published:[3682,null], reads:2, refreshes:2}`. The probes expose private entry points and seed a synthetic linked state in memory; they do not edit production files or contact a real game. This is an additional remaining path, not a regression introduced specifically by the round-3 guard.
