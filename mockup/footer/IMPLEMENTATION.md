# Porting the footer

Peter approved this design on 18 Sep 2026. The canvas is
https://claude.ai/artifact/1YVEPZP4CCjKKTxK1VBvAC; its source is `project/*.dc.html`
beside this file, generated by `build_footer_canvas.py`. Read `project/Main.dc.html` first:
every size, colour and hover rule you need is in it, and its `.ft` tokens are the board's
own (`--ground`, `--surface`, `--ink-2`, `--accent`, ...), so port the rules onto the
board's variables and drop the `.ft` token block.

Work in this worktree (`C:/Users/Peter/Coding_Projects/big-copilot-footer`, branch
`footer-redesign`). Read `AGENTS.md` before anything else. Commit when the tests pass;
push, PR and deploy only if Peter says so.

## What Peter asked for

- "Vote on features" and "Support the project" stand out from everything else.
- Links to socials (YouTube, the Big Ambitions subreddit) and to the official game pages
  (Steam, Hovgaard Games).
- The not-affiliated disclaimer.
- A light/dark switch.
- Impressum and Privacy on the sideline: small, last, never competing with the rest.

## The design, top to bottom

1. The top rule, with the green sphere resting on its left end. The sphere is static here.
2. Two door cards in a two-column grid. Vote: filled accent button, opens the community
   dialog. Support: outlined accent button with a heart, goes to `DONATE_URL`. On hover a
   card lifts 2px and its border turns accent; the vote arrow nudges, the heart beats.
   All of it is off under `prefers-reduced-motion`.
3. Three link columns with mono headings (Big Copilot / Follow / Big Ambitions · official)
   and the theme switch on the right.
4. The sideline: wordmark, the disclaimer sentence, then Impressum · Privacy · Game build
   in mono 11px at the far end.

Phone (`project/Phone.dc.html`, below about 640px): cards stack with full-width buttons,
the columns become a two-column grid, every link and switch button is 44px tall, the
sideline stacks.

Text uses `--ink-2`, not `--ink-3`, wherever it is small: `--ink-3` fails 4.5:1 on both
grounds.

## Where the code is now

Find these by anchor, not line number.

- Board footer: `<footer class="foot" id="footer">` in `TEMPLATE`, CSS under
  `/* footer ---`. The board script fills `#footFile` and `#footBuild`
  (`$("footBuild").textContent = ...`). `#footerLinks` holds the Changelog button.
- The same template becomes the CLI's `dashboard.html`, which has no `app.js`, no
  `community.js` and no `impressum.html` next to it.
- Landing footer: `<footer class="rv">` inside `BANNER` in `build_web.py`, CSS `.lg-links`,
  `.lg-group`, `.lg-colophon`. Link constants `REPO`, `ISSUES_URL`, `DONATE_URL`,
  `YOUTUBE_URL` are in `build_web.py`.
- Landing and board are in the DOM together (`body.has-board` decides which shows), so ids
  must stay unique across both footers.
- `web/app.js`, in the `onBoard()` branch: moves the `#footSlot` links into the More menu
  (`#menuFootSlot`) and clones issue, donate, Impressum and Privacy into `#footerLinks`.
- `web/community.js`: `voteButton()`, `insertLandingControls()`, `insertBoardControls()`.
  One delegated click handler opens the dialog for any `[data-community-open]`.
- No theme switch exists. The CSS already honours `:root[data-theme="light"|"dark"]` and
  falls back to `prefers-color-scheme`; nothing sets the attribute.
- `web/impressum.html` and `web/privacy.html` carry their own copy of the tokens and only
  follow `prefers-color-scheme`.

## Steps

1. **Constants.** Move `REPO`, `ISSUES_URL`, `DONATE_URL`, `YOUTUBE_URL` next to `GAME_URL`
   in `ba_dashboard.py`, add `REDDIT_URL = "https://www.reddit.com/r/bigambitions/"` and
   `MAKER_URL` for Hovgaard Games, and have `build_web.py` import them. Open both new URLs
   and confirm they resolve before committing them; ask Peter if either does not. Keep the
   comment on `DONATE_URL` about never using the RentenWiki page.
2. **One footer, two homes.** Write the footer markup once in `ba_dashboard.py` and
   substitute it into the template and into `BANNER`, so the landing and the board cannot
   drift. Use classes and `data-` attributes inside it, no ids, because both copies are in
   the DOM. Prefix every new class `ft-`. Keep `#footFile` and `#footBuild` working: the
   file name stays a board-only element in the sideline beside the build.
3. **What each home shows.**
   - Site board and landing: everything.
   - CLI `dashboard.html`: no vote door and no legal links, since neither works offline.
     Render the vote door `hidden` and let `community.js` unhide it in
     `insertBoardControls()` and `insertLandingControls()`. Make the door grid
     `repeat(auto-fit, minmax(320px, 1fr))` so a lone Support card fills the row.
     Leave the legal slot empty in the template; `app.js` keeps cloning `impressumLink`
     and `privacyLink` into it, and the landing copy carries them as real links.
   - The landing keeps "Where saves live" (`#helpLink`); put it first in the Big Copilot
     column there.
4. **Doors.** The vote button keeps `data-community-open`, `aria-haspopup="dialog"` and the
   `feature-new` badge with `data-new-feature="community-voting"`. The Changelog button
   keeps `data-changelog` and its badge. Do not put the online count in the footer:
   `tests/community-browser.test.cjs` pins it to the masthead.
5. **More menu.** Leave `#menuFootSlot` as it is. `app.js` still needs link elements with
   the ids `issueLink`, `videoLink`, `donateLink`, `sourceLink`, `impressumLink`,
   `privacyLink` to move there, so keep a hidden source for them in `BANNER`, or build them
   in `app.js` from the footer's links. Stop cloning issue and donate into the board
   footer; the template has them now.
6. **Theme switch.** Three buttons in a `role="group"`: match system, light, dark, each
   with `aria-pressed`. Put the logic in the board script so the CLI gets it too:
   - store the choice in `localStorage` under `ledger_theme` (`"light"`, `"dark"`, absent
     for system), wrapped in try/catch like the other `ledger_` keys;
   - set or remove `data-theme` on `<html>`;
   - apply the stored value in a tiny inline script in `<head>` before first paint, so a
     light-theme visitor never sees a dark flash;
   - one switch updates every copy of the control (landing and board).
   Then check what reads the theme outside CSS: grep `web/map.js`, `web/wiki.js` and the
   board script for `prefers-color-scheme` and `matchMedia`, and make each follow
   `data-theme` first. The privacy notice promises specifics about browser storage; read
   `web/privacy.html` and add the theme key to its list if the list is exhaustive.
   `impressum.html` and `privacy.html` should honour the same key with the same head
   script and a `:root[data-theme]` block.
7. **Remove what this replaces:** `.foot-colophon`, `__COLOPHON__` in the template,
   `.lg-links`, `.lg-group`, `.lg-colophon`, `.lg-footlink`, and the comment above the
   landing footer. Keep `COLOPHON` only if something still uses it; the sideline sentence
   is shorter on purpose: "Fan-made companion for Big Ambitions. Not affiliated with,
   endorsed by or supported by Hovgaard Games."
8. **Changelog.** The theme switch is a new capability, so it gets an entry in
   `web/changelog.json`; the restyle does not. Format: `docs/contributing.md`.

## Traps

- CSS classes are global: `.door`, `.cta`, `.seg`, `.orb`, `.live`, `.mono` from the
  canvas must be renamed with the `ft-` prefix. `.orb` already exists on the board.
- Tests slice source by comment strings. `tests/resume.test.cjs`,
  `tests/save_location.test.cjs` and `tests/performance.test.cjs` do it in `web/app.js`;
  check them before editing comments in the `onBoard()` branch.
- `tests/restore.test.cjs` ("the Impressum and privacy notice stay reachable") selects
  `#footerLinks a[href=...]`. Either keep `id="footerLinks"` on the board's legal slot or
  update the test with the new selector.
- External links keep `target="_blank" rel="noopener"`.
- Fonts are self-hosted on the site; add no font or icon request. Icons are the inline
  stroke SVGs from the canvas.
