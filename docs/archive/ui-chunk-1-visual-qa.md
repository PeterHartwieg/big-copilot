# Chunk 1 independent visual, responsive and accessibility QA

Candidate: `356af7b` in the frozen review worktree. Tested 26 September 2026 in headless Microsoft Edge through Playwright. The boards use only `tests/fixtures/payload_snapshot/data_day47_history.json`, a derived long-name version of it, and the synthetic `.hsg` from `tests/save_fixtures.py`. I inspected rendered images of the candidate and approved round-three reference, then interacted with the candidate using keyboard and pointer. No candidate files were changed.

## Findings

1. **P2 — The phone Overview pushes the first critical action below the initial viewport.** At 390 px, dark or light, the candidate uses four large KPI cells across two rows. Needs attention starts at approximately y=391 and the first critical action starts at y=743, partly under the fixed bottom navigation in an 844 px viewport. At 320 px, Needs attention starts around y=441. The approved phone reference uses a one-line Profit/Cash/Day summary; Needs attention starts around y=128 and the first action is visible around y=320. The browser-hosted synthetic save adds a status card and puts Needs attention around y=600, below most of the first viewport. This weakens the approved attention-first entry. Compact the phone KPI summary and preserve an immediately visible critical summary/action while retaining the four figures elsewhere. Evidence: [reference phone](reference-390-dark.png), [candidate phone](candidate-390-dark.png), [candidate light](candidate-390-light.png), [hosted loaded save](host-loaded-390.png).

2. **P2 — Long names and enlarged text cause horizontal overflow and clipped findings.** At 390 px, replacing only the fixture's company/site display names with realistic long names gives `documentElement.scrollWidth=454` for a 390 px viewport. The HART. Brewery replacement extends past the right edge of a critical row, taking its title with it. At 320 px with ordinary names, scroll width is already 333 px because the condensed Needs attention bar's two buttons extend to x=333. At 130% CSS zoom, 390 px becomes 432 px scroll width and the 320 px case also becomes 432 px; the Show more button and condensed bar exceed the viewport. Wrap/break the site-name flex content and allow the condensed bar/buttons to shrink or stack; verify with long display names and 130% text. Evidence: [long-name phone](long390.png), [130% phone](zoom390.png), [130% narrow phone](zoom320.png), [normal 320](candidate-320-dark.png), measurements in [stress.json](stress.json).

3. **P2 — Keyboard focus is lost across finding navigation and return.** In the live-source synthetic board at desktop 1440, focus the first “Resolve staff demand” link and press Enter. The route changes to `#site/eighthstreet-5` and the arrival strip names the origin, but `document.activeElement` becomes `body`. Pressing Tab lands on “Portfolio,” skipping any focused arrival/heading. Clicking the arrival strip's Needs attention return button changes back to `#overview`, again leaving focus on `body`; the next Tab lands on the Profit KPI rather than the originating finding. Move focus to a stable destination heading or arrival context on navigation and restore it to the originating finding/action on return. Evidence: [livecheck.json](livecheck.json), [destination screenshot](candidate-live-arrival.png).

4. **P2 — An unselected severity filter fails text contrast, especially in light theme.** On the phone Overview, click the “4 critical” filter. Its still-operable `aria-pressed=false` label is rendered with `opacity:.45`. Measured effective contrast is **3.98:1 dark** and **2.85:1 light**, below the 4.5:1 normal-text target. Use an opaque inactive color with sufficient contrast while retaining a visible selected state. Other sampled KPI, finding, action and task-directory text measured at least 4.56:1 in light and 4.97:1 in dark. Evidence: [contrast.json](contrast.json), [light inactive filter](filter-off-light.png), [dark inactive filter](filter-off-dark.png).

5. **P3 — Negative profit uses a positive-looking graphic.** In the supplied synthetic fixture, yesterday's profit is `-$628`, yet its amount is white and its sparkline green in desktop and phone, dark and light. The approved reference renders the negative amount and sparkline red. The current green line obscures the meaning of the result, particularly when the red change chip is small. Apply the negative semantic style to both amount and sparkline for a loss. Evidence: [candidate desktop](candidate-1440-dark.png), [candidate phone](candidate-390-dark.png), [reference desktop](reference-1440-dark.png).

6. **P3 — The shared phone masthead omits the day/source readout shown in the approved reference.** At 390 px with the live-source synthetic board, the masthead shows only the company mark, New badge and Search; the desktop version shows Day 47 and LIVE. The approved phone design retains “Live · updated … ago” and a compact day figure. In the browser-hosted file flow the separate source card says “Up to date” and shows a save timestamp, but the current game day is still absent from the phone masthead. Put a concise day/source indicator in the phone shell without reintroducing the tall KPI block. Evidence: [live desktop](candidate-live-1440.png), [live phone](candidate-live-390.png), [approved phone](reference-390-dark.png), [hosted save](host-loaded-390.png).

7. **P3 — Approved masthead orb is absent.** The approved 1440, 1024 and 768 masthead reference has a green sphere balancing the main navigation and clock. The candidate has only the small wordmark dot at those widths. The shell otherwise adopts the palette and thin rules, but this is the clearest missing playful brand element in the shared shell. Add the responsive orb treatment if still part of the approved masthead, with the specified reduced-motion behavior. Evidence: [reference 1440](reference-1440-dark.png), [candidate 1440](candidate-1440-dark.png), [reference 1024](reference-1024-dark.png), [candidate 1024](candidate-1024-dark.png).

## Passed coverage

Coordinator addendum after targeted follow-up: finding 7 is corrected. At 1440 px the sphere appears after its entrance delay in both normal and reduced motion. At 1024 px it is hidden by responsive CSS in both modes. This is not a missing desktop decoration or a reduced-motion defect. The text-only enlargement follow-up independently reproduced overflow (399 px scroll width at 390 and 320 px). See the private `qa-visual-c1/supplement.md` and its evidence.

- Rendered desktop 1440 and 1024, tablet 768, phone 390, narrow 320; dark and light at desktop/phone; reduced-motion contexts; 130% CSS zoom; long company/site labels. Browser-hosted `web/index.html` loaded a synthetic save through Pyodide and displayed populated findings.
- Needs attention follows KPI metrics and precedes All tools. All four critical findings were present before “Show 8 more”; Details starts closed and is visually distinct from the action. The page retains bars, mini charts and task-panel illustrations. All 13 All tools task links were present.
- Enter opens Details, with a visible focus outline. Enter on All tools jumps to the directory and focuses its heading; the sticky All tools button remains visible within a long list and works by keyboard. Customize checks opens by keyboard; Escape closes it and restores focus to its opener. No page script errors appeared in the CLI/live checks.
- Representative normal text/control contrast passed in both themes apart from the unselected severity filter above. The phone finding actions measured 44 px high; bottom navigation items 52 px high. No ordinary-name horizontal overflow at 390, 768, 1024 or 1440.

## Limits

No physical phone or screen reader was used. The 130% condition was emulated with CSS zoom, matching the design reference method, rather than operating-system text scaling. I did not audit the later-chunk internals of Supply, Staffing, Businesses or Expansion, all finding kinds, write flows, game-link behavior, company switching, or the full regression suite. Browser-hosted testing used a local static server; its community-presence POST received 501 because that API is not served by a static file server, unrelated to this shell review.

Evidence files and reproduction scripts are confined to this directory. The candidate worktree remains at `356af7b`.
