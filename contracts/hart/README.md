# HART companion version 1

`HARTModPack.Companion.CaptureV1(GameInstance)` returns JSON on the main thread, or null without a current matching save. It never changes game state, warms item/billing caches or logs. `CompanionSave` separately publishes the report under `hartmodpack:companion` on the public save callback. Only that key is written or removed. The publisher stays attached when legacy HardModePatch makes gameplay stand down.

The report identifies `provider: hart-mod-pack`, schema version 1, mod version and exact character/day/hour/whole minute. Each module has version 1, status `ready`, `disabled`, `unavailable` or `failed`, data and a nullable semantic reason. Non-ready data is null. Empty ready arrays mean known empty; missing data never means zero. Nested Cafe and held-record modules use the same shape. A ready model may declare an inactive feature: readiness means its reported facts are known, not that the rule is on.

`runtime` reports actual owner activity, legacy blocking, the RLO decision already made (accepted/refused/undecided/absent), target hook states and every requested/effective rule. A failed read has effective null. Selected rules with a known missing hook or fail-open gate have effective false. Multiple distinct provider assemblies return no capture; two mod instances from one assembly share one owner and publisher.

`rent` publishes `hart-rent-v1`, a residential type id and residential/other multiplier in thousandths. Multipliers affect new market rent, rounded up to whole money. Existing signed leases stay unchanged. Prefer native live rent/deposit quotes; offline use needs known native baseline and no other unmodelled rent provider.

`runningCosts` publishes `hart-running-costs-v1`, independent equipment and office IT states, constants and all registered item classifications. Missing classification is unknown. `currentSites` addresses are objects with street and number. `inputBasis` distinguishes current items and the next bill's cached load; a read never populates or clears billing caches. `itSeatDayCents` is a conditional component for `itDay`, not a new historical debit. `itBasis: included-in-rlo-internet-accrual` means never add it to an observed RLO accrued value. Unknown Internet owner state is null with `itStatus: unavailable`; disabled/offline/outage has known zero. The outage rule matches billing: the day an outage started is free, not merely its hours. RLO owns tariffs, season, base floor use and money conversion.

For each power/water day, clamp hours to 0..24. If hours are zero reconstruct full use with `rloUse * 1000 / 250`, otherwise use rloUse. Integer divisions truncate. Standby is `full * 250 / 1000`; open floor use is `full * 750 * hours / (1000 * 12)`. Power is max(standby, alwaysWatts*24) + open + openWatts*hours. Water is standby + max(open, litresPerOpenHour*hours). Negative base use is returned unchanged. Office seats cost 15000 cents/month at level 1000: clamp level to 500..4000, integer multiply/divide by 1000, then round `(cents + monthDays/2)/monthDays`, minimum monthDays 1 and cap 536870911. No charge without an active Internet account or on its outage-start day.

`factoryPurchases` publishes `hart-factory-purchase-gate-v1`, purchase-only restriction, effective gate, definitions and typed preserved held records. Definition `baseFeeCents` is not an effective enrollment quote. RLO `education` version 1 owns current eligibility, qualifications, paid/loan enrollment, grants, retakes and duration. Charge once per missing course, not per machine; already-owned machines have no retroactive requirement. Unknown held format is unavailable, not empty. The catalogue can remain injected after stand-down, while the gate is inactive.

`retailDemand.cafe` publishes `hart-cafe-stations-v1`, two sessions per usable station/hour and current paired station counts. Pairing uses common furniture roots, excludes missing requirements and refuses unaudited requirement predicates without invoking them. Hypothetical plans need proven pairs. Ambience remains individually unavailable while owner score/preset/eligibility is unavailable (`ambience-owner-inputs-unavailable`); offices are unchanged. Native registered Bakery/vehicle prices are observations, not repeated HART multipliers.

Money uses integer cents. Ratios use thousandths. Output is deterministic, UTF-8 at most 4 MiB, at most 10000 array/object rows, depth 16, text 1..1024 UTF-16 units, integers within JavaScript exact range. Ordinary reports are clock-validated captured facts: removing the provider and saving at the same clock can retain an indistinguishable report. Bound Link captures add live freshness; clock equality alone does not.

Generate fixtures and parity vectors with `tools/CompanionCheck` against the built pack and reviewed game reference DLLs. These are synthetic offline checks, not native gameplay acceptance. A changed RLO binary must receive exact target-body and hash review before adding it to the pack's reviewed hashes; a new companion contract does not bypass the gate.
